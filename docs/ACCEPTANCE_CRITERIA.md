# 项目验收量化标准

本文件把项目要求转换为可测量、可复现的验收标准。每个指标都给出目标值、测量方法和
证据位置。后续执行报告按这些编号逐项判定；未达到的标为“未通过”，不用主观描述替代。

## 1. 实验网络

| 编号 | 指标 | 目标值 | 测量方法 |
|---|---|---|---|
| N1 | 路由器数量 | ≥ 3 台 | 统计设备台账中 `role` 含“路由器”或型号为 IOSv 的设备 |
| N2 | 交换机数量 | ≥ 3 台 | 统计设备台账中 `role` 含“交换机”或型号为 IOSvL2 的设备 |
| N3 | 测试终端数量 | ≥ 3 台 | 统计 `device_type=linux` 的终端/服务器 |
| N4 | 管理接口可用性 | 6/6 台网络设备 SSH 可登录 | Netmiko 逐台执行只读命令 |
| N5 | VLAN 配置覆盖 | 3/3 台交换机至少 1 个 active VLAN | `show vlan brief` 输出解析 |
| N6 | 路由配置覆盖 | 3/3 台路由器至少 1 条默认/静态/动态路由 | `show ip route` 输出解析 |
| N7 | ACL 配置覆盖 | ≥ 1 台设备存在 ACL | `show access-lists` 输出解析 |
| N8 | 正常业务连通性 | 预设 4 条业务路径 4/4 成功 | 从指定设备执行 ping，记录源/目的/时间 |
| N9 | 设备台账字段完整性 | 9/9 台具备名称、站点、角色、管理 IP、类型 | 检查 `network/device_inventory.json` 与运行时台账 |

## 2. 状态采集

| 编号 | 指标 | 目标值 | 测量方法 |
|---|---|---|---|
| C1 | 采集状态类型 | 每台网络设备 ≥ 4 类（接口/路由/配置/邻居或 ACL 等） | 检查 `collection_items` 的 `capture_type` |
| C2 | 采集时间完整性 | 100% 状态事实有 `observed_at_utc` | SQL 统计空值 |
| C3 | 设备标识完整性 | 100% 状态事实关联设备名和采集批次 | SQL 关联 `devices/collection_runs` |
| C4 | 真实采集成功率 | 可达设备 SSH 命令成功率 ≥ 95% | 采集摘要 `ssh_commands_success/failed` |
| C5 | 不可达语义 | 不可达设备标记 `unreachable/failed`，不使用历史成功状态补齐 | 对应单元测试 + 检查最新批次 |
| C6 | 原始证据保留 | 成功/失败采集项均保留 `raw_blob_id` 或 `error_message` | SQL 统计 |
| C7 | 采集批次发布 | 100% 演示采集有 `published_at_utc` 和 `run_id` | 检查 `collection_runs` |

## 3. 运维知识库

| 编号 | 指标 | 目标值 | 测量方法 |
|---|---|---|---|
| K1 | 知识条目数量 | ≥ 20 条 | 统计 `articles.json` |
| K2 | 类别覆盖 | VLAN、路由、DHCP、ACL、接口故障各 ≥ 3 条 | 按 `category` 统计 |
| K3 | 元数据完整性 | 100% 条目有来源、适用设备、版本 | 检查字段非空 |
| K4 | 检索命中率 | 6 个领域查询中 ≥ 5 个 Top 3 命中对应类别 | 固定查询集 + `retrieve(top_k=3)` |
| K5 | 测试答案隔离 | 0 条知识文章包含完整测试问题或标准答案 | 字符串匹配全部 `SCENARIOS` 问题 |
| K6 | 检索审计 | 100% 诊断保存 top_k、命中条目、排名、来源 | 检查 `retrieval_queries/retrieval_hits` |

## 5. 故障诊断

| 编号 | 指标 | 目标值 | 测量方法 |
|---|---|---|---|
| D1 | 输出字段完整性 | 6/6 字段：现象、证据、原因、检查、建议、复测 | 逐条答案检查 |
| D2 | 证据引用有效性 | 100% `evidence_used.observation_id` 存在于本次证据 | 自动比对 |
| D3 | 设备引用有效性 | 100% 设备名存在于本次证据或缺失说明 | 自动比对 |
| D4 | 知识引用有效性 | 有知识库时 ≥ 80% 原因包含 `kb_refs` | 自动统计 |
| D5 | 诊断准确率 | 有知识库 ≥ 80%（correct + 0.5×partial） | 10 场景评测 |

| D7 | 证据不足处理 | 缺失信息非空，且不编造端口/状态 | `INSUFFICIENT_EVIDENCE_01` |
| D8 | 正常场景误报 | `NORMAL_01` 不得断言链路中断/路由缺失/ACL 拦截 | 评测脚本 forbidden 词 |
| D9 | 响应时间记录 | 100% 诊断有模型耗时和全链路耗时 | SQL/评测结果 |

## 判定规则

- **通过**：所有带“100%/0 个/≥”的硬指标达到目标；
- **部分通过**：核心功能达到，但存在明确未测量项或非阻断缺口；
- **未通过**：任一硬指标未达到，或只能用预置文本/历史状态伪造现场证据。

执行报告必须给出每个编号的实测值、证据位置和结论，不能只写“已完成”。
