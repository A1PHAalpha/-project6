# 控制台设计说明

## 1. 目标

控制台用于发现异常、追溯设备事实和形成可核查的诊断结论。它是高密度运维工作台，
不是面向公众的产品官网。信息优先级依次是当前状态、证据来源、可执行建议和安全边界。

## 2. 信息架构

当前生产实现保留五个一级入口：

1. 总览
2. 设备与采集
3. 诊断中心
4. 运维知识库
5. 设置

变更、评测和完整治理流程仍由旧版页面提供。设计不以“用新页面覆盖全部旧功能”为目标，
而是先把高频运维路径收敛到统一工作台。

## 3. 页面规则

### 总览

- 指标展示设备可达、最新采集、知识库和待排查数量。
- 拓扑使用当前设备、站点、链路和已发布状态事实动态生成。
- 右侧展示当前问题、最近诊断和采集批次。
- 主操作是“开始诊断”，拓扑整体进入诊断中心。

### 设备与采集

- 设备台账是运行时权威来源。
- 设备详情包含当前事实、接口、采集历史和原始输出。
- 新增、修改和软退役设备都记录台账版本。
- 采集计划、立即采集和后台任务状态在同一页面可见。

### 诊断中心

- 拓扑、诊断正文和 AI 助手共同构成工作台。
- 结论按“问题、工具调用、结论、证据、建议、知识依据、复测”展示。
- 证据必须带设备名和采集时间。
- AI 助手只提供建议；打开终端和快速操作都要求人工确认。

### 知识库

- 展示活跃索引、文章、模型、版本和最近命中。
- 构建任务显示进度；成功后发布新索引，旧版本保留。
- 当前界面聚焦查看和构建，文章编辑属于后续能力。

### 设置

- 只开放白名单环境变量。
- 敏感值始终掩码，提交掩码或空值表示保留旧值。
- 保存后提示重启，不热切换正在使用的模型或凭据。

## 4. 视觉系统

| Token | 值 | 用途 |
|---|---|---|
| `--bg` | `#070D18` | 页面底色 |
| `--panel` | `#0F1A2C` | 主面板 |
| `--panel-2` | `#132238` | 次级面板和表头 |
| `--line` | `#1E3049` | 边框和分隔线 |
| `--text` | `#E7EEF8` | 主文字 |
| `--text-2` | `#A9B8CD` | 次文字 |
| `--accent` | `#38D3F5` | 主操作和焦点 |
| `--green` | `#3ED598` | 成功和可达 |
| `--amber` | `#F5B94C` | 待确认和部分成功 |
| `--red` | `#F2777A` | 失败和风险 |

界面使用系统无衬线字体，ID、IP 和命令使用等宽字体。卡片圆角 12px，按钮和输入框
圆角 8px。桌面端保持运维台的信息密度，移动端将侧栏收敛为抽屉并允许表格横向滚动。

## 5. 状态表达

- 状态同时使用颜色、文字和必要的图标，不能只靠颜色区分。
- “未采集”“不可达”“证据不足”是三个独立状态。
- 设备事实必须显示时间和来源；模型判断不能伪装成设备事实。
- 错误提示包含可执行下一步，不只显示异常类型。
- 加载、空数据、部分失败和权限不足都必须有明确界面。
